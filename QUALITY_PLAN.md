# ScamShield quality assurance plan

## Quality model

This plan uses ISO/IEC 25010 quality attributes and the supplied Secure SDLC framework:

- **Functional suitability:** tests cover parsing, deterministic tools, upload validation, voice routing,
  health, and fabricated evaluation loading.
- **Reliability:** bounded model steps, timeout, retry/backoff, explicit API failure fallback, and no
  success-shaped fallback for malformed verdicts.
- **Security:** threat model, risk register, Trusted Host, CORS, CSP, upload limits, static URL analysis,
  secret/dependency/SAST CI gates, and non-root container.
- **Performance efficiency:** in-memory processing, request/byte limits, no URL fetches, bounded retries,
  and process-local rate limiting.
- **Maintainability:** typed Python, Ruff, mypy, pytest coverage gate, package boundaries, Makefile, and
  small reviewable commits.
- **Usability/accessibility:** bilingual UI, keyboard focus states, mobile layout, clear verdict states,
  copyable report, and explicit error/loading states.

## Required gates

Every pull request must pass:

1. `python -m ruff check .`
2. `python -m mypy scamshield app.py tools.py eval/run_eval.py`
3. `python -m pytest -q` with the configured coverage threshold
4. `python -m bandit -r scamshield app.py tools.py -q`
5. `python -m pip_audit`
6. Gitleaks secret scan
7. `git diff --check`

Release evidence must also include the fabricated evaluation output, a reviewed threat model, and a
deployment configuration review.

## Quality exceptions

The current coverage threshold is 60% because external API and streaming failure branches require
integration fixtures; the deterministic tools and schemas have higher direct coverage. Raising the
threshold should accompany mocked model/ASR integration tests, not an arbitrary number change.

No benchmark, accuracy, latency, or safety claim is valid unless it is generated by a committed script
and its inputs, output, and limitations are retained.
